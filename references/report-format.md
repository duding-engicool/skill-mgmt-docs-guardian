# 报告结构与字段说明

## 一、变更影响报告（`reports/YYYY-MM-DD_变更影响报告.md`）

章节顺序是刻意设计的：

```
标题与元信息
  ↓
⚠️ 分析盲区            ← 必须置顶，不允许藏到附录
  ↓
一、变更概要            新增/删除/重命名/实质变更/仅元信息/需复核
  ↓
二、变更明细
  2.1 新增
  2.2 删除
  2.3 实质内容变更      ← 逐文件列出条款级或单元格级前后对照
  2.4 仅元信息变更
  2.5 重命名/移动
  ↓
三、影响分析            按 高/中/低 置信度分组，每条带依据
  ↓
四、一致性问题          失效引用 / 版本脱节 / 孤立文件
  ↓
五、待办清单            指向 CSV
  ↓
六、产物索引
```

### 盲区为什么必须置顶

如果 5% 的文件没解析，而其中恰好是一份被引用的核心程序文件，整份影响分析就是漏的——但用户毫不知情。**让用户误以为分析是全覆盖的，是这个工具最危险的失败模式。**

### 变更明细的字段

| 字段 | 说明 |
|---|---|
| 变更类型 | 修改 / 新增 / 删除（对应 diff 的 replace / insert / delete） |
| 条款 | 段首识别出的条款号，如 `5.2`；识别不到则为空 |
| 变更前 / 变更后 | 归一化文本，截断至 120 字 |

单元格变更额外带：工作表名、单元格地址（`B3`）。

单文件明细上限 200 条，超出会标注"已截断"。

## 二、待办清单（`reports/YYYY-MM-DD_待办清单.csv`）

UTF-8-BOM 编码，Excel 双击不乱码。列：

`序号 | 受影响文件 | 相对路径 | 责任人 | 影响距离 | 置信度 | 触发源 | 依据 | 状态`

已标注为忽略的项不进入此清单。可直接分发给各文件责任人。

## 三、体系台账（`reports/体系台账.csv`）

每次扫描都刷新。列：

`编号 | 标题 | 相对路径 | 格式 | 版本 | 生效日期 | 责任人 | 最后修改人 | 解析状态 | 解析备注 | 被引用次数`

用途：
- 首次扫描的主产出（基线模式下没有变更报告）
- 判断编号规则是否生效：看"编号"列是否大面积为空
- "被引用次数"可用于识别核心文件

## 四、STATUS.md（给 Agent 读的交接笔记）

每次扫描后重写。包含：上次/本次快照时间、纳管文件数、变更数、需复核数、盲区数、最近产物路径、Agent 行动提示。

**Agent 每次调用本技能必须先读它。** 因为 Agent 的会话没有记忆，状态只能落在磁盘上。

## 五、关系图（`reports/YYYY-MM-DD_关系图.html`）

单文件、内嵌力导向布局、**不依赖 CDN、不发起网络请求**，双击即开。

- 全量视图：所有文件及其引用关系
- 变更影响视图：只看本次变更文件 + 其 1 跳邻居（**这是主视图**，全量图几百个节点会糊成毛线球）
- 支持搜索定位、拖拽固定、滚轮缩放、点击查看引用进出
- 橙色描边 = 本次变更；灰色虚线圈 = 未解析（盲区）
