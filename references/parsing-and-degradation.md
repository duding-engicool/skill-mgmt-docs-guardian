# 各格式解析规则与降级策略

## 一、支持的格式

| 格式 | 依赖 | 抽取内容 |
|---|---|---|
| `.docx` | python-docx | 段落（含标题层级）、表格、页眉、核心属性（最后修改人/标题） |
| `.xlsx` / `.xlsm` | openpyxl | 每个工作表的单元格（上限 5000 个非空单元格/表） |
| `.pdf` | pdfplumber | 文本层按行切分；无文本层则判定为扫描件 |
| `.pptx` | python-pptx | 每页文本框段落 |
| `.txt` / `.md` / `.csv` | 无 | 按行 |

## 二、不支持、给出转换建议的格式

| 格式 | 提示信息 |
|---|---|
| `.doc` | 老版 Word 格式，建议另存为 .docx |
| `.wps` / `.et` / `.dps` | WPS 专有格式，建议另存为 Office 格式 |
| `.jpg` / `.png` / `.tif` | 图片，需 OCR，建议转为可编辑文本 |
| 其他 | 暂不支持的格式 |

这些文件**不会中断扫描**，会以 `parse_status=failed` 进入台账，并在报告开头的盲区声明中列出。

## 三、降级三原则

1. **绝不因单个文件失败而中断整体扫描。** 解析异常被捕获并转成 `failed` 状态，附异常摘要。
2. **依赖缺失不崩溃。** 缺 python-docx 时，docx 全部标记为"缺少依赖"，并提示安装命令，其余格式照常处理。
3. **解析成功但无正文 → `partial`。** 例如空文档、纯图片 docx。这类文件不进盲区计数，但会在台账中标注。

## 四、为什么必须用"解析后内容的哈希"

Word/Excel 文件只要打开再保存，即使一个字没改，内部 XML 与 zip 时间戳也会改变。

若用原始文件哈希做比对，会出现满屏"文件已修改"但打开看不出任何变化的假变更——用户看两次就不会再信这个工具。

因此本工具：

- 把每个文件解析成统一结构（条款序列 / 单元格集合）
- 对**归一化后的文本**计算 SHA-256 作为 `content_hash`
- 只有 `content_hash` 变化才判定为内容变更

归一化规则：去除零宽字符、全角空格，合并连续空白。**不做标点全半角转换**，避免引入误判。

## 五、元数据抽取位置

版本号、生效日期、责任人通常在：

- Word 的**页眉**
- 首页**封面表格**
- 正文前 40 个段落

因此解析器会额外读一遍页眉和表格，并用"关键词 + 冒号 + 值"的模式匹配。若抽不到，检查 `config.json` 里的 `version_keys` / `effective_date_keys` / `owner_keys` 是否覆盖你们文件的实际字段名。

## 五之二、老版 .doc 的转换（Windows）

纯 Python 读不了 `.doc`（OLE2 复合文档里的 WordDocument 流）。若目标目录里 `.doc` 占多数，
不转换就会有大面积盲区，影响分析失去意义。用：

```
python scripts/convert_docs.py --path "<绝对路径>"
```

要点：

- 输出到 `.cb-index/converted/`，**副本**，原文件不动；`scan.py` 自动优先解析副本
- 依赖 `pywin32`，需要本机装了 Microsoft Office 或 WPS
- WPS 模拟 `Word.Application` 时，关闭最后一个文档会让它整个退出，
  脚本靠"常驻一个空白文档"规避；进程若中途被杀会自动重启续跑
- `SaveAs2` 在 Word 2007 及更早版本不存在，脚本自动回退 `SaveAs`
- 转换过的副本不要删（上百份逐个转很慢），`--reset` 已特意保留 `converted/`

## 六、Excel 的特殊处理

Excel 不是"另一种文档"，处理方式与 Word 完全不同：

- **不做段落级 diff**，改为**工作表级 + 单元格级 diff**（哪个 sheet、哪个单元格、旧值 → 新值）
- 单元格数量上限 5000/表，防止超大文件拖垮运行
- 反过来，Excel 常是**建图的黄金数据源**：文件清单台账、职责矩阵往往直接给出了层级关系
